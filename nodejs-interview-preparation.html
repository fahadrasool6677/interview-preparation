Each phase is interview-shaped: concept, why it works that way, a production example, common traps, then senior follow-ups. Teaching content comes after the assessment.

Recommended study order

Order is interview-weighted, not course-catalog order

Senior Node interviews fail people on async internals, HTTP/data correctness, SQL, and design — not on knowing every TS utility type. This sequence front-loads what gets asked first and hardest.

Default sequence (before assessment customization)

  1. JavaScript deep revision — everything else is built on the event loop and async mental model.
  2. Node.js internals — the role’s core; request path, blocking, workers, shutdown.
  3. REST + HTTP + Express architecture — this is most of the “backend” onsite.
  4. PostgreSQL + Prisma — correctness and performance; Prisma is a tool, SQL is the interview.
  5. Auth & security — expected at senior level; shallow JWT answers get follow-ups.
  6. Redis & caching — almost every scale discussion lands here.
  7. Performance & production debugging — how seniors actually sound.
  8. TypeScript (intermediate → advanced) — after runtime fluency; type-level depth is a plus, not the gate.
  9. Queues, Pub/Sub, event-driven flows — needed for “order placed” designs.
  10. Microservices & sagas — after you can design a solid modular service.
  11. System design (progressive, then 10 problems) — uses all of the above as vocabulary.
  12. Coding interview (backend-flavored + DSA) — parallel after week 1, not instead of Node.
  13. Docker, deploy, CI — enough to be credible; not a cloud-cert track.
  14. Testing strategy — after you have code and APIs to test.
  15. Capstone projects / story bank — turn revision into interview narratives.
After the assessment: any topic you score below 7/10 moves up and gets extra daily quiz + a second pass. Coding stays a daily 30–60 minutes even when the “phase” is later.

Topic priority

High / Medium / Low for Node and senior backend interviews

Low does not mean “skip forever”. It means do not spend week 1 there unless the assessment shows a hole.

Priority Topics Why
High Event loop & async JS, Node architecture, HTTP/REST, Express structure, Postgres (indexes, transactions, isolation), auth (JWT/session/OAuth at a practical level), caching, idempotency, error handling, debugging slow/broken APIs, system design fundamentals, medium coding (hash maps, two pointers, trees as needed) These decide offers. Interviewers probe until they find the edge of your model.
Medium TypeScript advanced types, Prisma performance, Redis locks/Pub/Sub, queues & delivery semantics, RBAC design, rate limiting, pagination (cursor), Docker/Nginx/CI, Jest strategy, worker threads vs cluster, GraphQL (if the company uses it) Expected at senior; you need clean answers, not encyclopedia depth on day 1.
Low Generators, Symbols, WeakMap trivia, every mapped/conditional type, gRPC internals, Kubernetes deep dive, 2PC theory without saga practice, exotic FP, covering 100% of DSA patterns Nice if asked; a weak event-loop answer costs more than a missing infer example.

How to study

Each session has the same six moves

Interviews reward spoken structure. Practice answering in this shape: definition → why → production example → trade-off → follow-up you expect.

How to speak an answer

  1. One-sentence claim.
  2. Mechanism (event loop, index, token, queue — the actual why).
  3. A real scenario (orders, webhooks, cache, pool).
  4. Failure mode and how you would detect it.
  5. Trade-off versus the obvious alternative.

Scoring (used after each topic)

1–10 on correctness, depth, practical instinct, communication, senior judgment. Below 7: that topic returns to the tracker as Weak and is first tomorrow.

Interview mode later: one question at a time, no instant answer key.

Initial assessment

Twenty questions to locate your current level

Answer as you would in a senior interview: short enough to say in 2–4 minutes, specific enough to be wrong. Do not look up answers. Rate confidence honestly. There is no answer key on this page.

After you submit, use “Copy answers for chat” and paste into this conversation. Weak areas will be used to reorder the roadmap. Skip blanks only if you truly would freeze in an interview — that is still useful data.
1. Event loop order
High · JS

For this snippet, state the print order and why (which queues). Then say what would change on the Node event-loop if the then callback did a 200ms CPU spin.

console.log('A');
setTimeout(() => console.log('B'), 0);
Promise.resolve().then(() => console.log('C'));
setImmediate(() => console.log('D'));
console.log('E');

2. Request path
High · Node

Walk through what happens inside Node from “TCP data arrives for an HTTP request” to “response bytes leave”, including libuv and the JS event loop. Where does your Express middleware actually run?

Confidence:
3. 10,000 concurrent requests
High · Node

How does Node hold 10k open connections without 10k OS threads doing JS? When does this story break (CPU, GC, pool size, downstream latency)?

Confidence:
4. CPU vs I/O
High · Node

You must resize images and also call three HTTP APIs. Compare: block the event loop, worker_threads, child process, offload to a queue + worker pool. What do you choose and why?

Confidence:
5. Types at the boundary
Medium · TS

When do you use interface vs type? When is unknown correct and any a bug? How do you keep a Prisma/Express handler type-safe if the request body is untrusted JSON?

Confidence:
6. Production architecture
High · Express

Sketch a production Node API layout (folders/layers). Where do transactions live? How do errors reach a client without leaking stacks? What is a smell that “service” is just a second controller?

Confidence:
7. Order API
High · REST

Design HTTP APIs for placing an order (create, pay, cancel, get). Include status codes, idempotency keys, and what you return if payment is retried. Do not write a novel — interview-length.

Confidence:
8. Duplicate payments
High · REST

A client double-submits “pay order 99” because of a timeout. How do you prevent double charge at API, DB, and (if used) queue consumer? Name the failure if you only “check then insert” without a unique constraint.

Confidence:
9. Isolation
High · Postgres

You debit a wallet. Contrast Read Committed vs Repeatable Read vs Serializable for lost updates. What lock or constraint would you actually use in production?

Confidence:
10. N+1
High · Prisma

Describe an N+1 you have seen (or a realistic one) with Prisma. How do you confirm it, fix it, and when is raw SQL the honest choice?

Confidence:
11. Cache stampede
High · Redis

An expensive product API is cached 60s. Key expires at a traffic spike. What happens, and how do you prevent stampede (lock, probabilistic early expire, singleflight, stale-while-revalidate)? What must never be cached the same way as a product title?

Confidence:
12. JWT vs session
High · Auth

SPA + Node API: access + refresh tokens vs server session. Logout, theft of a token, and rotation. What goes in the cookie flags?

Confidence:
13. Public API hardening
High · Security

You expose a public REST API. List the top threats you would actually budget for (not a dump of the OWASP name list) and one concrete control each. Include SSRF if the API fetches user-supplied URLs.

Confidence:
14. Delivery semantics
Medium · Queues

Order Created is published. Payment, inventory, notify consume it. Why is exactly-once usually a lie? How does an idempotent consumer look? What is the DLQ for?

Confidence:
15. Saga vs split
Medium · Services

When are microservices a bad idea for a 5-person team? If you still split order / payment / inventory, how do you handle a payment success + inventory fail without 2PC?

Confidence:
16. URL shortener
High · Design

45-minute design: functional + non-functional requirements, API, schema, hash collisions, redirect path at high QPS, what you cache, what fails. Write the outline you would say out loud.

Confidence:
17. Latency incident
High · Debug

p50 was 500ms; now p99 is 10s (p50 maybe still fine). Step-by-step: what you look at first, what you rule out, how you tell event-loop block vs DB vs downstream vs pool exhaustion vs GC. No tool-name dump without purpose.

Confidence:
18. Mocking
Medium · Test

For an order service that talks to Postgres, Stripe, and Redis: what do you mock in unit tests, what do you use a testcontainer/local for, and what is a false-green test you have seen (or can invent)?

Confidence:
19. Concurrency limiter
High · Coding

Describe (or sketch) async function mapLimit(items, limit, fn) in JavaScript. How do you handle a rejection? How is this different from a queue with prefetch 1?

Confidence:
20. CAP in products you know
High · Design

For (a) a product catalog read and (b) a wallet balance: what do you sacrifice under partition, and what does the user see? Tie it to a cache or replica choice you would actually ship.
