Execution context

High
Concept

Each call creates a lexical environment, variable environment, and this binding. Creation and execution phases explain hoisting, closures, and lookup.

Why it works this way

JavaScript resolves identifiers through environment records linked to outer scopes; this lets a function retain lexical access without copying every value.

Running example
const tax = 0.1;
function total(amount) {
  const fee = amount * tax;
  return amount + fee;
}
console.log(total(100));

Call stack

High
Concept

The stack records synchronous frames and return addresses. Deep recursion can overflow it, while asynchronous continuations re-enter through queued callbacks.

Why it works this way

A single stack gives deterministic run-to-completion semantics, but any long frame blocks all other JavaScript in that agent.

Running example
function charge() { throw new Error("declined"); }
function checkout() { charge(); }
try { checkout(); } catch (e) {
  console.log(e.stack.split("\n").slice(0, 3).map(x => x.trim()).join(" -> "));
}
Runs in-browser; console.log is captured 
Error: declined -> at charge ... -> at checkout ...

Event loop

High
Concept

The event loop runs one task, drains eligible microtasks, allows rendering or host work, then selects another task.

Why it works this way

Run-to-completion prevents concurrent mutation inside one turn; host queues provide concurrency without executing two JS frames simultaneously.

Closures

High
Concept

A closure combines a function with references to its lexical environment, enabling private state, factories, and callbacks.

Why it works this way

Captured bindings remain reachable while the function is reachable; this is powerful but can retain large object graphs.

Running example
function idempotencyGuard() {
  const seen = new Set();
  return key => seen.has(key) ? "duplicate" : (seen.add(key), "accepted");
}
const guard = idempotencyGuard();
console.log(guard("pay-1"), guard("pay-1"));
